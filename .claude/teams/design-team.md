# Design Team

## Purpose

Default team for product UX, UI layout, design-system consistency, and brand-sensitive visual work that is broader than a single comment or one-off polish tweak.

## Lead

- `@product-designer` for app flows, information architecture, onboarding, and product-surface UX
- `@brand-designer` for identity-sensitive marketing surfaces, hero sections, and broader visual direction

## Supporting Agents

- `@ui-designer`
- `@design-systems-architect`
- `@customer-advocate`
- `@product-owner`
- `@tech-writer`

## Typical Triggers

- app or dashboard layout direction
- onboarding, settings, or navigation UX
- landing pages, README heroes, or brand-sensitive presentation surfaces
- reusable UI patterns or design-system cleanup
- visual consistency review before implementation or publication

## Default Flow

- clarify the primary surface, audience, and user goal
- shape the flow or visual direction at the right level first
- tighten layout, hierarchy, and component choices
- check whether the work is one-off art direction or should become reusable system guidance
- surface concrete recommendations, follow-up implementation needs, and any trust or clarity risks through `@master`

## Required Gates

- `@design-systems-architect` before treating a repeated UI pattern or shared visual rule as stable system guidance
- `@customer-advocate` when the main risk is user confusion, onboarding friction, or trust loss
