# /envision

## Purpose

Interview the user in a structured but lightweight way to clarify what should be built before jumping into implementation.

In practice, this means `@master` should interview the user in small rounds, help them compare options, and let them decide the direction before execution planning begins.

## Owned By

- Lead: `@vision-partner` or `Product Discovery Team`
- Common support: `@product-owner`, `@customer-advocate`, `@idea-executor`, `@strategy-reviewer`
- Orchestrator: `@master`

## What It Should Do

1. ask small high-signal questions to clarify the build
2. help the user decide what matters most
3. propose 2 to 3 viable directions when useful
4. recommend a best-fit direction with trade-offs
5. roll out the next implementation steps clearly
6. hand off to `/plan-idea` when the direction should become an execution plan

## Output

- clarified build brief
- options and recommendation
- explicit next-step rollout
- optional `/plan-idea` recommendation
